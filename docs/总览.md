# 技术全链路发展学习计划：Java + Go + 嵌入式C++

## 一、核心战略定位

你的身份不是"想转行的Java工程师"，而是"具备7年Java工程经验、正在叠加Go云原生与嵌入式C++能力的复合型后端工程师"。

- **Java是基本盘**：存量系统维护、改造、重构的岗位不会消失，7年经验是资产而非包袱。
- **Go是增长极**：云原生岗位缺口大，Go开发者稀缺，溢价来自"能解决云原生实际问题的人"，而非"会写Go语法的人"。
- **嵌入式C++是长期护城河**：机器人行业的核心技术栈，学习曲线最陡，但一旦形成能力，薪资天花板和不可替代性最高。

> 三条线不是三选一，而是有主有次、逐步叠加。前期以Go为主攻方向，Java保持基础维护，嵌入式C++作为长期探索。

## 三、分阶段详细学习清单

### 第一阶段：Go基础 + 云原生入门（第1-2月）

#### 3.1 Go语言核心

**目标**：从Java思维切换到Go思维，能写出生产级Go代码。

| 学习模块 | 具体内容 | 与Java的差异要点 |
| --- | --- | --- |
| 语法基础 | 变量声明（`:=`）、函数多返回值、包管理 | Go函数可直接定义在包下，无需类包裹 |
| 结构体与方法 | `type ... struct`、指针接收者、大小写控制访问权限 | 没有class关键字，用结构体+方法替代 |
| 接口 | 隐式实现、空接口、接口组合 | Go的接口是隐式的，不需要implements声明 |
| GMP调度模型 | Goroutine、M、P的调度关系 | 面试必考点，理解Go并发的底层 |
| Channel | 有缓冲/无缓冲、select、超时控制 | 用通信替代共享内存，与Java的BlockingQueue思路不同 |
| 错误处理 | error接口、defer、panic/recover | 没有异常机制，错误是返回值 |
| 内存管理 | GC机制、逃逸分析、sync.Pool | 与JVM GC对比理解，Go的GC更轻量 |

> **避坑提醒**：不要试图在Go里找"Go版的Spring"。很多Java转Go的新手最大的坑就是试图搞一套复杂的注解系统，Go的哲学是"约定大于配置"。

#### 3.2 Java JVM诊断能力（辅助，学到"能诊断"即可）

不需要深究源码级，但需要：

- 看懂GC日志，理解CMS/G1/ZGC的基本差异
- 能用jstack/jmap定位简单线程和内存问题
- 理解JVM内存模型（堆、栈、方法区）的基本结构
- 线程池核心参数（corePoolSize、maxPoolSize、队列类型）的设计逻辑

> **为什么在Go阶段还要学JVM？** 因为你的Java存量经验是迁移的基础。JVM调优中"诊断-分析-优化"的思维模式，在Go的pprof分析中完全适用，只是工具不同。

#### 3.3 Docker + Kubernetes入门

| 模块 | 学习内容 | 实践方式 |
| --- | --- | --- |
| Docker | 镜像/容器/仓库核心概念、Dockerfile编写、多阶段构建 | 把现有Java项目容器化 |
| K8s基础 | Pod/Deployment/Service/Ingress、kubectl基本命令 | 用Minikube本地搭建单节点集群 |
| Helm | Chart模板化部署 | 用Helm部署一个简单应用 |

> **阶段产出**：能用Go写一个RESTful API服务，并用Docker容器化部署到本地K8s集群。

### 第二阶段：Go云原生实战 + 高并发架构 + 嵌入式C++入门（第3-5月）

#### 3.4 Go云原生深化

| 模块 | 学习内容 | 实践方式 |
| --- | --- | --- |
| Web框架 | Gin / Go-Zero | 用Gin搭建完整的后端接口 |
| ORM | GORM | 替代Hibernate的思维，理解Go的DB操作范式 |
| 服务网格 | Istio基础概念 | 理解流量管理、熔断、可观测性 |
| 云原生项目 | 完成一个完整的云原生实战项目 | 直接填补简历空白，企业要的是能解决问题的开发者 |

> **推荐项目方向**：设备管理平台、API网关、OTA升级服务。这些项目与机器人行业的平台层需求高度重合。

#### 3.5 高并发与分布式（语言无关的核心能力）

无论Java还是Go，分布式系统的核心问题是相同的：

- **服务拆分与事务一致性**：理解最终一致性、幂等性、Saga模式
- **缓存策略**：Redis的使用场景、缓存穿透/击穿/雪崩的解决方案
- **消息队列**：Kafka/RocketMQ的削峰填谷、异步解耦
- **分布式锁**：Redis实现、Redisson原理
- **可观测性**：Prometheus + Grafana监控体系

> **关键认知**：调查显示74%的Java转Go开发者指出Go在高并发网关场景下内存占用降低约58%，P99延迟从120ms降至35ms——性能优势是真实的，但前提是你理解"高并发网关"的设计逻辑。

#### 3.6 嵌入式C++入门

**目标**：理解嵌入式C++与普通C++的本质区别，能写基础的硬件驱动代码。

| 模块 | 学习内容 | 关键差异 |
| --- | --- | --- |
| 嵌入式C++ vs 普通C++ | 嵌入式C++是安全导向的子集：无动态内存、无异常、无RTTI、最小化STL | 需要"降级"思维，放弃很多高级特性 |
| 位操作与硬件访问 | volatile、const、static在寄存器操作中的用法 | 直接操作硬件地址 |
| MCU架构 | STM32/ESP32/Cortex-M基本架构 | 理解资源受限环境 |
| 通信协议 | GPIO、ADC、PWM、SPI、I2C、UART | 机器人传感器和执行器的基础接口 |
| 实践项目 | 光传感器+LED PWM调光、UART命令接口、I2C温度传感器读取 | 从简单外设开始 |

> **阶段产出**：完成一个Go云原生项目 + 能写基础的嵌入式C++驱动代码。

### 第三阶段：项目深化 + 机器人平台层 + 嵌入式C++进阶（第6-8月）

#### 3.7 机器人云平台项目（求职核心项目）

| 模块 | 技术要点 |
| --- | --- |
| 设备接入 | MQTT协议实现设备与服务端双向通信 |

## 七、核心原则

1. **项目驱动学习**：永远用真实项目驱动，不要只看教程。企业招Go开发，要的是能解决实际问题的开发者，项目经验永远比背知识点重要。
2. **Java是跳板不是包袱**：7年Java工程经验是迁移的认知基础，不是需要清零的负债。82%的Java转型者具备Spring Boot微服务经验，他们的优势恰恰是领域建模能力和分布式理解。
3. **不追求三线齐头并进**：Go是主攻，Java是维持，嵌入式C++是长期布局。前期80%的精力在Go上，嵌入式C++从第2个月开始逐步加入。
4. **数学不是障碍**：平台层/云服务开发不需要线性代数、控制理论。嵌入式C++的RTOS和驱动开发也不需要高深数学，只有算法方向才需要。
5. **先进门再深入**：你的切入点不是"从零学机器人"，而是"把已有的后端工程能力，应用到机器人的平台层"。先进门，在平台层站稳脚跟，再决定是否向更底层的嵌入式或算法方向探索。
