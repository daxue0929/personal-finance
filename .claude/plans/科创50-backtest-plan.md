# 科创50 定投止盈回测 — 实施计划

## 目标
用 `index_info` 表中的科创50指数(000688)回测用户指定策略,生成含**每次止盈明细**(时间/金额/持仓等)的报告,并给出可优化方向。沿用 `tasks/backtest_hs300_dca.py`(V1)的既有分析脚本模式,不接入生产调度。

## 策略规格(用户已确认重装规则)
| 项 | 设定 |
|---|---|
| 标的 | 科创50(index_code=000688),收盘价模拟净值 |
| 定投 | 每个交易日 300 元,自 2020-02-03 起不间断(无论涨跌) |
| 止盈档位(持仓收益率) | ≥10% 卖当时持仓 30%;≥15% 卖 30%;≥20% 一次性卖出全部(100%) |
| 档位重装 | **仅 20% 清仓后重装**(用户选择):10%/15% 触发后本轮不再触发,直到一次 20% 清仓才三档重装 |
| 每日顺序 | 先以当日收盘价定投买入,再判定止盈 |
| 成本结转 | 平均成本法(按比例结转,卖出不改变平均成本) |
| 回款处理 | 止盈回款留作现金,不自动再投(匹配用户简单策略;再投列为优化方向) |
| 费用 | 不计交易费用/分红/税收 |

## 数据(已核实)
`index_info where index_code='000688' and del_flag='1'`:1562 交易日,2020-02-03 ~ 2026-07-09,收盘价 643.04 ~ 2207.86,无空值/零值。

## 交付物
1. **`tasks/backtest_kc50_dca.py`** — 回测脚本
   - `fetch_prices()`:复用 `app.utils.config.DB_CONFIG` + raw pymysql(与 V1 一致)
   - `run_backtest(prices, rearm_mode='on_clear')` → `(events, summary)`:纯函数引擎
     - `rearm_mode='on_clear'`=用户选择;`'on_dip'`=跌破10%重装(V1风格),用于敏感性对比
   - `_xirr(cashflows)`:资金加权年化(从 V2 移植,提升严谨度)
   - `build_report()`:生成 markdown;`main()`:跑主策略 + on_dip 变体(敏感性) + 写报告
2. **`tasks/test_backtest_kc50_dca.py`** — `unittest` 测试(TDD 先写,stdlib 无需装 pytest)
   - 合成价格验证:10%/15%/20% 阈值触发、20%清仓归零、**仅20%后重装(不因跌破10%重装)**、比例卖出平均成本不变、XIRR、多周期循环
3. **`tasks/科创50_定投止盈_回测报告.md`** — 报告章节:策略与假设 / 数据概览 / 回测汇总(含 XIRR、区间最高收益率) / **止盈事件明细(用户核心诉求)** / 按年分布 / 敏感性(on_clear vs on_dip) / 可优化方向 / 说明与风险

## 可优化方向(报告第七节 + 对话总结,针对科创50高波动成长风格)
1. 回款再投(子弹池):止盈回款低位加速抄底,复利(沪深300 V2 已验证)
2. 均线/估值加权定投:低估多投高估停投,压低平均成本(科创50波动更大,潜力更高)
3. 重装策略:on_dip 比 on_clear 多触发10%档小止盈,提高周转(敏感性表量化)
4. 止盈档位动态化:结合 PE 分位/波动率调整阈值(科创50 PE 字段当前为 0,需先补数据)
5. 20%不全清,保留底仓吃趋势(科创50趋势性强)
6. 定投金额随估值/回撤调整

## TDD 流程
先写测试(合成数据,定义预期)→ 跑测试失败 → 实现引擎 → 跑测试通过 → 跑真实数据生成报告 → 校验合理性(止盈次数/金额/收益率与科创50历史走势吻合)。
