# PRD：基金列表页定投计划入口改造

> 文档版本：v1.0　|　创建日期：2026-07-15　|　状态：已确认需求，待实现
> 关联功能：基金定投自动化（已实现）、基金信息管理页（FundManage.vue）

---

## 1. 概述（Introduction / Overview）

### 1.1 背景与问题

基金定投自动化功能已于上一轮上线：用户可在**基金编辑弹窗**内配置定投计划（频率+金额，单基金多规则），净值更新任务命中当天自动插入买入流水。但当前定投管理的入口藏在「编辑基金」弹窗里，存在两个体验问题：

1. **定投情况不可见**：基金列表页表格无任何定投信息列，用户无法一眼看出哪些基金配了定投、配了几条规则，必须逐个点开「编辑」才能查看。
2. **搜索区分两个字段**：基金代码和基金名称是两个独立输入框，用户往往只记得代码或名称片段，需在两个框间切换尝试，不够便捷。

### 1.2 解决方案

对基金信息管理页（FundManage.vue）做两项前端改造：

- **搜索区合并**：基金代码、基金名称两输入框合并为**一个下拉搜索框**，输入关键字同时匹配代码和名称，下拉选项展示「代码 - 名称」，选中后按代码精确过滤列表。
- **定投计划列**：表格新增「定投计划」列，单元格显示该基金定投概要（条数+频率摘要，如「3条：每日/周三/月10号」或「无」），点击单元格弹出**定投计划管理弹窗**，弹窗内可对该基金的定投计划做增删改查（CRUD）。原编辑弹窗内的定投区块移除，定投管理统一收口到列表页独立弹窗。

### 1.3 核心设计原则

- **复用现有后端**：定投 CRUD 接口（`/api/dip-plans`）上一轮已建好，本次不新增定投后端逻辑；仅新增一个轻量「基金关键字搜索」后端参数。
- **单一入口**：定投计划管理统一到列表页独立弹窗，移除编辑弹窗内重复区块，避免两处 UI 维护。
- **概要可见**：定投列用概要文案让定投情况一览无余，点击进入详情管理。

## 3. 用户故事（User Stories）

**US-1　一站式搜索基金**
> 作为基金持有人，我想在搜索区用**一个下拉框**输入代码或名称片段就能搜到基金，不必在「基金代码」「基金名称」两个框之间切换，快速定位目标基金。

**US-2　一眼看出定投情况**
> 作为基金持有人，我想在基金列表表格里直接看到每只基金的定投概要（配了几条、什么频率），无需逐个点开编辑弹窗翻看，快速掌握全盘定投布局。

**US-3　从列表直达定投管理**
> 作为基金持有人，我想点击某只基金行的「定投计划」单元格，直接弹出该基金的定投计划列表，在弹窗里增删改定投规则，不必先进编辑弹窗再找定投区块。

**US-4　弹窗内管理定投**
> 作为基金持有人，我想在定投计划弹窗里新增定投规则（选频率、选日期、填金额）、启停某条规则、删除规则，操作完弹窗列表即时刷新，关闭后表格概要也同步更新。

## 4. 功能需求（Functional Requirements）

### FR-1　搜索区合并为下拉搜索框

- **FR-1.1** 移除搜索区原有的「基金代码」「基金名称」两个 `el-input`，合并为一个 `el-select`（`filterable` + `remote` + `clearable`）。
- **FR-1.2** 下拉搜索框输入关键字时，调用 `GET /api/funds`（新增 `keyword` 参数）远程搜索，返回同时匹配代码或名称的基金，选项 label 为「{基金代码} - {基金名称}」，value 为基金代码。
- **FR-1.3** 选中某基金后，按其 `fund_code` 精确过滤列表（列表查询仍用 `GET /api/funds?fund_code={选中代码}`，与原 fund_code 模糊搜索行为一致）。
- **FR-1.4** 「基金类型」下拉筛选项保留不变。
- **FR-1.5** 「搜索」「重置」按钮保留。重置时清空下拉搜索框选中值。

### FR-2　后端基金关键字搜索参数

- **FR-2.1** `GET /api/funds` 新增可选 `keyword` 参数：当传入 `keyword` 时，按 `fund_code LIKE '%keyword%' OR fund_name LIKE '%keyword%'` 过滤（与现有 `fund_code`/`fund_name` 参数互斥优先级：`keyword` 非空时忽略 `fund_code`/`fund_name`）。
- **FR-2.2** `FundInfoStorage.get_funds_with_pagination` 新增 `keyword` 参数，构建 OR 条件查询。
- **FR-2.3** 下拉搜索框请求时 `page_size` 设较大值（如 50），保证下拉选项足够。

### FR-3　表格新增定投计划列

- **FR-3.1** 在「备注」列与「操作」列之间新增「定投计划」列。
- **FR-3.2** 列单元格内容：
  - 该基金**无启用/无定投计划**：显示灰色文字「无」。
  - 有定投计划：显示概要，格式「{条数}条：{频率摘要}」。频率摘要拼接各计划文案（如「每日」「每周三」「每月10号」），多条用「/」分隔；超过2条时截断显示「等N条」。
  - 概要文案用 `el-button`（link 样式）或可点击文本，鼠标悬停提示「点击管理定投计划」。
- **FR-3.3** 点击单元格（任意有/无计划都可点）打开该基金的定投计划管理弹窗。

### FR-4　定投计划管理弹窗（独立）

- **FR-4.1** 新增独立 `el-dialog`，标题为「定投计划 - {基金代码} {基金名称}」。
- **FR-4.2** 弹窗内表格展示该基金全部定投计划：列含「频率」（文案，复用 `frequencyText`）、「金额(元)」、「启用」（`el-switch` 启停）、「操作」（删除）。
- **FR-4.3** 弹窗内「+ 添加定投计划」按钮，点击展开新增行：频率下拉（每日/每周/每月）、条件日期下拉（weekly 选周几、monthly 选几号、daily 无）、金额输入（`el-input-number`，>0）。
- **FR-4.4** 新增计划调 `POST /api/dip-plans`，必填 `fund_code`、`dip_frequency`、`dip_amount`（>0）；weekly/monthly 必填 `dip_day`。
- **FR-4.5** 启停切换调 `PUT /api/dip-plans/{id}`（`enable_dip`），失败回滚开关。
- **FR-4.6** 删除调 `DELETE /api/dip-plans/{id}`，二次确认。
- **FR-4.7** 弹窗内任意 CRUD 操作成功后，刷新弹窗内列表；关闭弹窗时刷新外层基金表格（让定投概要列同步更新）。
- **FR-4.8** 弹窗数据来源：`GET /api/dip-plans?fund_code={代码}`（已存在接口）。

### FR-5　移除编辑弹窗内定投区块

- **FR-5.1** 移除编辑/新增基金弹窗内的「定投计划」`el-divider` 区块及关联的表格、新增行 UI。
- **FR-5.2** 移除 `showEditDialog` 中 `fetchDipPlans` 调用（编辑弹窗不再加载定投数据）。
- **FR-5.3** 保留 `dipPlanApi`、`frequencyText`、频率/日期选项等可复用到独立弹窗的逻辑；将原弹窗内定投 CRUD 函数（`fetchDipPlans`/`addDipPlan`/`toggleDipEnable`/`removeDipPlan`）改造为服务于独立弹窗（操作目标基金由当前弹窗上下文的 fund_code 决定，而非 `formData.fund_code`）。

### FR-6　表格定投概要数据获取

- **FR-6.1** 基金列表加载后，为当前页每只基金查询定投计划，组装概要。采用**按基金批量查询**避免 N+1：列表当前页 N 只基金，调用 `GET /api/dip-plans`（不传 fund_code 取全部启用）一次，前端按 fund_code 分组映射到各行。
  - 备选：若「全部启用」接口不返回已停用计划导致概要不准，则后端新增「按多个 fund_code 批量查询」或前端并行单查。实现阶段确认 `get_enabled_plans` 是否含停用计划，按需调整。
- **FR-6.2** 概要计算纯函数 `dipSummary(plans)`：输入某基金的定投计划数组，返回概要文案字符串。便于测试。

## 5. 非目标（Non-Goals / Out of Scope）

- **NG-1** 不改动定投后端核心逻辑（任务触发、份额计算、幂等等），仅复用现有 `/api/dip-plans` CRUD。
- **NG-2** 不实现定投计划的「编辑已有规则」（仅新增/启停/删除；与上一轮编辑弹窗行为一致）。
- **NG-3** 不做定投计划的多选批量操作。
- **NG-4** 不改动基金列表的其他列、分页、导出功能。
- **NG-5** 不改动基金新增/编辑表单的其他字段。
- **NG-6** 智能定投（dip_mode=smart）仍预留，不在本次实现。

## 12. 技术考量（Technical Considerations）

- **远程搜索复用**：`el-select` remote 模式，输入调 `GET /api/funds?keyword=xxx&page_size=50`，避免新建接口。
- **关键字 OR 查询**：后端 `keyword` 用 SQLAlchemy `or_(fund_code.like(...), fund_name.like(...))`。
- **概要纯函数**：`dipSummary(plans)` 纯函数抽到 utils 或组件内，TDD 覆盖（0条/1条/多条/截断）。
- **定投 CRUD 函数复用**：上一轮 `fetchDipPlans/addDipPlan/toggleDipEnable/removeDipPlan` 改造为接收 `fundCode` 参数，服务于独立弹窗上下文，不依赖 `formData`。
- **概要数据源**：列表加载后并行/批量取定投计划。倾向「一次取全部启用计划」前端分组，避免 N+1。
