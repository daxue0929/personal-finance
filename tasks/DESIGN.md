# DESIGN.md — 用户登录特性前端设计

> 由 `/frontend-design` 产出。本规范是质量门禁的依据（CLAUDE.md 要求实现须符合本文件，不符则返工）。

## 0. 设计立场

现有应用是「Element Plus 默认主题 + 纯内联样式 + 深石板侧边栏 + 金色高亮」的功能型内部工具，无自定义字体、无全局 CSS。本特性的两条界面采用**两种不同的设计姿态**：

- **登录页**：全屏独立路由，是唯一有设计自由的位置。取一个可论证的审美风险——以应用**自身已有**的石板灰 `#545c64` 与金色 `#ffd04b` 为色系基础，把登录框定为「金库门」：深色、安静、一枚金色封印；通过它之后进入明亮的工作账本（现有浅色应用）。金色 = 价值/财富，深色 = 私密账本，二者皆来自理财主题自身，而非通用的「奶油+赤陶」或「酸绿+黑」AI 默认配方。
- **用户管理页**：刻意与 `TaskManage.vue` 保持一致（同一卡片骨架、同一搜索/表格/分页/弹窗模式、同一标签配色规则）。它的"设计"在于**字段集与状态细节**（角色标签、会话时长、密码只写、防自锁），而非新视觉身份。一致性在此优先于求新。

引子一句话：**登录是金库门（深色·金封），工作是打开的账本（浅色·清爽）。**

## 1. 色彩

**对比度**：金 `#ffd04b` 上压深石板 `#2c3033` 文字（对比度 ≈ 9:1，达标）；深面板上金色焦点环清晰可见。

## 2. 字体

不引入新字体（与现有应用一致 + 零新运行时依赖）。靠**字重/字号/字距**赋予登录页性格，而非换字族。

- **字族**（与现有应用相同系统栈）：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', Arial, sans-serif`
- **等宽**（仅登录深面板的"账本线"背景纹理用，非正文）：`'SF Mono', 'JetBrains Mono', Menlo, Consolas, monospace`
- **数字**：表格中 ID、会话时长等数字列加 `font-variant-numeric: tabular-nums`（理财工具的等宽对齐细节）
- **登录页字阶**：
  - 品牌标题「理财管理系统」28px / 700 / letter-spacing 2px（雕刻感，不换字族也有性格）
  - 副标语「定投 · 持仓 · 组合」13px / 400 / letter-spacing 4px / `rgba(255,255,255,0.45)`（大字距 = 铭牌感）
  - 表单标题「欢迎回来」20px / 600 / `--pf-ink`
  - 表单副标「登录以继续」13px / 400 / `--pf-ink-3`
  - 输入/标签 14px / 500
- **用户管理页字阶**：沿用 `TaskManage.vue`（标题随 `Layout` 顶栏 16px/500；表格默认；提示 12px/`#999`）。

## 4. 组件规范

### 4.1 登录页

- **品牌封印**：`◆` 金色菱形（16px，`--pf-gold`）+ 标题。无插图、无动画图标（已按"出门前取下一件配饰"原则裁掉）。
- **输入框**：EP `el-input` 默认尺寸，但去掉默认蓝焦点，改金焦点环（见 3.1）。用户名 `prefix-icon=User`，密码 `prefix-icon=Lock` + `show-password`。
- **登录按钮**：`el-button` 全宽，高 44px，深石板底 `--pf-slate-900` + 金字？否——金底深字更合"封印"语义：背景 `--pf-gold`、文字 `--pf-slate-900`、700、letter-spacing 4px「登 录」；hover `--pf-gold-press`。注意：这是登录页**唯一**的金底按钮，进入工作区后主按钮回到 EP 蓝。
- **进出场**：表单挂载时 200ms opacity 0→1 + 4px 上移；`@media (prefers-reduced-motion: reduce)` 下关闭。无其它动画（账本纹理是静态的）。
- **无障碍**：`<label>` 关联输入；回车提交；错误以 `role="alert"` 文本呈现（非仅色变）；焦点可见。

### 4.2 用户管理页

严格沿用 `TaskManage.vue` 的组件选型与交互，仅以下为本特性特有：

- **角色标签**：`admin` → `el-tag type="warning"` 文案「管理员」；`user` → `el-tag type="info"` 文案「普通用户」。
- **状态标签**：`enabled` → `type="success"`「启用」；否则 `type="danger"`「禁用」（与 TaskManage 完全一致）。
- **会话时长列**：`{n} 分钟`，`tabular-nums`，右对齐。
- **操作列**：「编辑」(small/默认) + 「删除」(small/danger)。**当前登录用户所在行**：删除按钮 `disabled` + `el-tooltip`「不可删除当前登录用户」。
- **会话时长输入**：`el-input-number`，`min=1 max=43200`(30天) `step=5` `default=60`，单位「分钟」紧跟其后（12px/`#999` 提示，与现有提示样式一致）；下方提示行「登录后保持登录态的时长，过期需重新登录」。
- **密码字段**：`type=password` `show-password`；编辑时 placeholder「留空则不修改」，非必填；新增时必填。
- **手动校验**（沿用现有 `if (!field) ElMessage.warning` 模式，不引入 `:rules`）：
  - 新增：用户名、密码必填；会话时长为空时默认 60。
  - 编辑：用户名恒在（禁用）；密码可空。
- **删除确认**：`ElMessageBox.confirm('确定要删除该用户吗？', '提示', {type:'warning'})`，与 TaskManage 一致。
- **角色/启用的自保护**：编辑「自己」时，角色 select 与启用 switch `disabled`，并在旁注 12px/`#999`「不可修改自身角色/状态」。后端同样拦截（403），前端 disabled 是第一道防误操作。

### 4.3 顶栏用户区（Layout.vue 增量）

现有 `el-header` 仅左侧标题。右侧增量（`justify-content: space-between` 已就位）：

```
[当前标题]                              [姓名 · 管理员●]  退出登录
```

- 当前用户名 + 角色小标签（admin 用 warning 色 mini tag，user 用 info）。
- 「退出登录」：EP 文本按钮（`link` 类型，`--pf-ink-2`，hover danger），无确认弹窗（登出低风险），点击 → `POST /api/logout` → 清前端登录态 → `router.push('/login')` + `ElMessage.info('已退出登录')`。
- 登录态来源：`GET /api/me`（HttpOnly Cookie 不可被 JS 读，故由后端探测）。当前用户存于新增的 `src/stores/auth.js`（一个 `reactive({user:null})` 共享模块，非 Pinia，供顶栏与用户管理页共用——跨页共享是引入它的唯一理由）。

## 5. 状态细节

### 登录页状态机
| 状态 | 表现 |
|---|---|
| 初始 | 两输入框空；登录按钮**禁用**（金底降不透明度 0.5）直到用户名与密码均非空 |
| 输入中 | 满足非空后按钮恢复可用 |
| 提交中 | 按钮 `loading`，输入框 `disabled` |
| 失败 | 表单下方 `role="alert"` 红字（`--pf-danger`），优先用后端 `error` 文案，默认「用户名或密码错误」；清空密码框并聚焦密码框 |
| 成功 | 跳转 `redirect` 查询参数或 `/` |

### 用户管理页状态机
| 场景 | 表现 |
|---|---|
| 加载 | 表格 `v-loading` |
| 空数据 | `el-table` 默认「暂无数据」（不自定义空状态，保持与同侪一致） |
| 新增成功 | `ElMessage.success('创建成功')` + 关弹窗 + 刷新 |
| 编辑成功 | `ElMessage.success('更新成功')` + 关弹窗 + 刷新 |
| 删除自己 | 前端按钮 disabled；若绕过则后端 403 → `ElMessage.error` 显示后端文案 |
| 非管理员访问 | 后端 403；前端菜单对该用户隐藏 `/system/users`（`v-if` 依 `auth.user.role==='admin'`） |

### 401 全局拦截（axios 响应拦截器）
- 任意接口 401 → 清 `auth.user` → `ElMessage.error('登录已过期，请重新登录')` → `router.push('/login')`（若已在登录页则不重复跳）。

## 6. 实现约束与一致性

- **不新增全局 CSS 文件**：沿用现有「内联样式 + EP 默认」现状。登录页自定义深色/金色样式写进 `Login.vue` 的 `<style scoped>`（含注释标注 token 名）；用户管理页用与 `TaskManage.vue` 相同的内联 hex。
- **不引入新 npm 依赖**：`@element-plus/icons-vue` 已被现有代码使用但未声明进 `package.json`，本次**顺手补声明**（固定到与 element-plus 2.5 兼容的版本，遵循 CLAUDE.md「倒数第二个稳定版」原则），并新增 `User`/`Lock` 图标导入。
- **路由**：`/login` 为顶层独立路由（`meta:{public:true}`，不套 `Layout`）；`/` 加 `meta:{requiresAuth:true}`，子路由继承；`router.beforeEach` 守卫：`public` 放行，需鉴权且无登录态 → `/login?redirect=...`。
- **登录态探测**：app 挂载时（`App.vue` `onMounted`）调一次 `GET /api/me`；成功存 `auth.user`，401 则不跳转（由路由守卫按需跳）。避免一进站就闪跳。

## 7. 自检（against AI 默认配方）

- ❌ 奶油+赤陶 / 酸绿+黑 / 报纸三栏——均未采用。深石板+金来自应用自身已有色与理财主题，可论证。
- ❌ 编号标记 01/02/03——本特性无序列内容，不用。
- ❌ 渐变光斑漂浮卡片登录背景——不用；用静态账本纹理替代。
- ✅ 张扬集中一处：金色只在登录页；工作区零金。
- ✅ 取下一件配饰：砍掉了动画封印/插图，仅留静态金菱形 + 纹理。
- ✅ 一致性：用户管理页与 `TaskManage.vue` 同骨架、同配色规则、同校验/确认模式。
- ✅ 无障碍：标签关联、回车提交、`role=alert` 错误、焦点可见、`prefers-reduced-motion`。
- ✅ 响应式：登录页 ≥768 分栏 / <768 堆叠。
