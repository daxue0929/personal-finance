# PRD：基金卖出流水功能

> 文档版本：v1.0　|　创建日期：2026-07-15　|　状态：已确认需求，待实现
> 关联功能：基金买入流水（已上线）、持仓分析（已上线）

---

## 1. 概述（Introduction / Overview）

### 1.1 背景与问题

当前系统已实现完整的基金**买入**链路：手动/快捷录入买入流水 → 定时任务按当日净值计算份额 → 加权平均成本法更新持仓。但系统**完全没有"卖出/赎回"概念**——全库 grep 确认无任何卖出相关表、任务或接口。

用户实际操作基金时会赎回份额（止盈、止损、调仓），目前无处记录，导致：

1. **持仓份额无法减少**：持仓表 shares 只增不减，与真实持有份额脱节，市值/盈亏失真。
2. **卖出收益无法追溯**：赎回实际到账多少钱、这笔卖出赚了多少（已实现盈亏）无据可查。
3. **缺少组合收益全景**：持仓分析页只有单持仓视角的盈亏率/市值走势，看不到"我的组合整体每天浮盈浮亏多少"的累计趋势。

### 1.2 解决方案

新增**基金卖出流水**功能，完全镜像现有买入流水的架构，并补齐组合级累计收益可视化：

- 卖出流水表 + 手动录入页面（录"卖出份额"，金额由任务计算）
- 定时任务按卖出当日净值计算卖出金额、已实现盈亏，并扣减持仓
- 持仓分析页新增"累计收益走势"折线图，支持单持仓/组合两种视角

### 1.3 核心设计原则

- **镜像买入**：表结构、状态机（PENDING→SUCCESS/FAILED）、任务驱动、手动刷新按钮、软删除均与买入侧对称，降低认知与维护成本。
- **卖出反向逻辑**：买入是"金额÷净值=份额"，卖出是"份额×净值=金额"；持仓更新方向相反（减少份额、记录已实现盈亏）。
- **不破坏现有数据**：卖出是纯增量功能，不改买入表、不回填历史。

## 3. 用户故事（User Stories）

**US-1　手动录入卖出**
> 作为基金持有人，我想在"基金卖出流水"页面手动录入一笔卖出（选基金、选日期、填卖出份额、选卖出类型），以便记录我的赎回操作。

**US-2　自动计算卖出金额**
> 作为基金持有人，我录入卖出份额后，希望系统在卖出当日净值可用时，自动算出"这笔卖出实际到账多少钱"（卖出金额=份额×当日净值），不必自己手算。

**US-3　手动刷新金额**
> 作为基金持有人，我不想等定时任务，希望点"刷新金额"按钮立即触发金额计算，尽快看到卖出金额和已实现盈亏。

**US-4　持仓自动扣减**
> 作为基金持有人，我卖出一笔后，希望持仓的份额、成本、市值、盈亏自动按规则更新，保持持仓数据与真实持有一致。

**US-5　查看每笔卖出盈亏**
> 作为基金持有人，我想在卖出流水表格里看到每笔卖出的"已实现盈亏"（赚了还是亏了多少），便于复盘。

**US-6　查看累计收益趋势**
> 作为基金持有人，我想在持仓分析页看到"累计收益走势"折线图——选某只基金看它每天浮盈浮亏，选"全部持仓"看组合整体每天总盈亏，从而判断整体收益趋势。

**US-7　防超卖**
> 作为基金持有人，我录入的卖出份额不应超过实际持仓份额，系统应阻止并提示，避免持仓出现负份额。

## 4. 功能需求（Functional Requirements）

### FR-1　卖出流水数据模型

- **FR-1.1** 新建卖出流水表，存储每笔卖出记录，字段见第 7 节"数据需求"。
- **FR-1.2** 同一基金同一天仅允许一条卖出记录（唯一约束 `fund_code + time`，与买入表对称）。当天重复录入则更新而非新增。
- **FR-1.3** 卖出类型 `type` 区分：`'1'`手动卖出 / `'2'`止盈卖出 / `'3'`止损卖出。
- **FR-1.4** 录入时必填：基金代码、卖出日期、卖出份额（>0）；卖出金额 `amt` 初始为空（NULL），由任务计算回写。
- **FR-1.5** 卖出状态 `sell_status`：`PENDING`（待处理）/ `SUCCESS`（成功）/ `FAILED`（失败），新建默认 PENDING。

### FR-2　卖出金额定时计算任务

- **FR-2.1** 新增定时任务 `calculate_seller_amount_task`，每小时执行一次（与买入份额计算任务对称）。
- **FR-2.2** 任务取所有 `sell_status='PENDING'` 的卖出记录，按卖出日期升序处理。
- **FR-2.3** 按**卖出日期精确匹配**取当日单位净值 `nav`（先查 fund_info：net_value_date 须等于卖出日期且 net_asset_value 非空；否则查 fund_nav_history 当日 unit_nav）。无法获取有效净值则跳过该条（保持 PENDING，等待下次执行）。
- **FR-2.4** 计算卖出金额：`amt = shares × nav`，四舍五入保留 4 位小数。**不扣手续费**。
- **FR-2.5** 计算已实现盈亏：`realized_profit = (nav − 持仓成本价 cost_price) × shares`，保留 2 位小数。
- **FR-2.6** 回写卖出记录：amt、nav、realized_profit、`sell_status='SUCCESS'`。

### FR-3　持仓扣减（任务算出金额时执行）

- **FR-3.1** 卖出金额计算成功后，按**加权平均成本法**扣减持仓：
  - 校验 `卖出份额 ≤ 持仓份额`，超卖则该卖出记录标记 `FAILED`，不扣减持仓。
  - `新份额 = 原份额 − 卖出份额`
  - `成本价 cost_price` **保持不变**（加权平均成本不因卖出改变）
  - `新成本金额 = 原成本金额 − 卖出份额 × cost_price`
  - `当前净值 current_price = nav`（卖出净值）
  - 重算 `当前市值 = 新份额 × current_price`、`盈亏 = 市值 − 新成本金额`、`盈亏率 = 盈亏/新成本金额×100%`
- **FR-3.2** 若该基金无持仓记录，卖出记录标记 `FAILED`（无持仓可卖）。
- **FR-3.3** 扣减时机：**在任务计算金额成功后立即扣减**（镜像买入侧"算出份额后才更新持仓"的设计），而非录入即扣减。
- **FR-3.4** 删除卖出记录**不回补**持仓份额（与买入侧删除不回退一致，避免历史数据被改动）。

### FR-4　卖出流水 Web API

- **FR-4.1** `GET /api/sellers`：分页列表，支持基金代码/名称模糊搜索、卖出类型/状态精确筛选、卖出日期范围、多字段后端排序。
- **FR-4.2** `GET /api/sellers/<id>`：查询单条卖出记录。
- **FR-4.3** `POST /api/sellers`：创建卖出记录，必填校验 fund_code/time/shares，shares>0。
- **FR-4.4** `PUT /api/sellers/<id>`：更新卖出记录。
- **FR-4.5** `DELETE /api/sellers/<id>`：软删除（del_flag='0'）。
- **FR-4.6** 统一返回格式：列表 `{data, total, page, page_size}`，单条操作 `{success, message, id}`，错误 `{error}` + 适当状态码。

### FR-5　前端卖出流水页面

- **FR-5.1** 新增菜单"基金卖出流水"，位于"基金买入流水"(sort 20) 与"基金信息管理"(sort 30) 之间，sort 值 25。
- **FR-5.2** 页面布局镜像买入流水页：顶部搜索区 + 功能区 + 数据表格 + 分页 + 新增/编辑对话框。
- **FR-5.3** 搜索条件：基金代码、基金名称、卖出类型（手动/止盈/止损）、卖出状态（PENDING/SUCCESS/FAILED）、卖出日期范围。
- **FR-5.4** 功能区按钮："新增卖出记录"(primary) + "刷新金额"(warning，手动触发 `calculate_seller_amount_task`，带 loading)。
- **FR-5.5** 表格列：ID、基金代码、基金名称、卖出日期、卖出份额、卖出金额（空显示"-"）、卖出净值、已实现盈亏（红涨绿跌着色）、卖出类型（el-tag）、卖出状态（el-tag）、备注、操作（编辑/删除）。全部支持后端排序，默认按卖出日期降序。
- **FR-5.6** 新增/编辑对话框：选择基金（远程搜索）、基金名称（自动填充 disabled）、卖出日期（必填，默认今天）、卖出份额（必填，>0）、卖出金额（disabled，显示"自动计算"）、卖出净值（disabled，显示"自动计算"）、已实现盈亏（disabled，显示"自动计算"）、卖出类型（下拉，默认"1"手动卖出）、卖出状态（下拉，默认 PENDING）、备注。
- **FR-5.7** 排序状态持久化到 localStorage（key `seller_sort_*`）。
- **FR-5.8** 删除前 ElMessageBox 二次确认。

### FR-6　持仓分析页累计收益走势图

- **FR-6.1** 持仓分析页持仓下拉**新增"全部持仓"选项**（位于列表首项）。
- **FR-6.2** 新增"累计收益走势"折线图，位于占比饼图下方（独立 el-card）。
- **FR-6.3** 图表口径随持仓下拉切换：
  - 选**单持仓**：展示该持仓每日未实现盈亏（profit_loss）序列。
  - 选**全部持仓**：展示组合级每日全部持仓未实现盈亏求和序列。
- **FR-6.4** 图表配色遵循 A 股涨红跌绿（正盈亏红、负盈亏绿），带 0 轴水面线，复用现有 `useEChart` composable。
- **FR-6.5** 时间范围跟随页面顶部 start/end_date 筛选。
- **FR-6.6** 无数据时显示 `el-empty`。

### FR-7　已实现盈亏汇总

- **FR-7.1** 卖出流水表格展示每笔已实现盈亏（FR-5.5 已含）。
- **FR-7.2** 持仓分析页概览卡片**新增"累计已实现盈亏"**：值为所有 `sell_status='SUCCESS'` 卖出记录的 `realized_profit` 之和，红涨绿跌着色。

### FR-8　持仓分析页"全部持仓"视角

> 为保证累计收益图"随持仓切换"体验一致，选中"全部持仓"时，现有图表也切换为组合级聚合视角。

- **FR-8.1** 选"全部持仓"时：
  - 盈亏率走势图：组合级每日盈亏率 = SUM(盈亏)/SUM(成本金额)×100%。
  - 市值走势图：组合级每日总市值 = SUM(市值)。
  - 占比饼图：保持最新日全部持仓占比（本就与单持仓无关）。
  - 累计收益走势图：组合级每日总盈亏（FR-6.3）。
  - 概览卡片：组合级最新总市值、最新总盈亏、区间最高/最低总市值、最大回撤、区间盈亏变化、累计已实现盈亏。
- **FR-8.2** 选单持仓时：所有图表维持现有单持仓行为不变。

## 5. 非目标（Non-Goals / Out of Scope）

- **NG-1** 不实现"快捷卖出"（买入侧有快捷买入，卖出侧不需要）。
- **NG-2** 不扣赎回手续费（金额=份额×净值，无 fee 概念）。
- **NG-3** 不自动回填历史卖出记录。
- **NG-4** 删除卖出记录不回补持仓份额（与买入删除不回退一致）。
- **NG-5** 不做多用户/多组合维度的卖出隔离（延续单用户设计）。
- **NG-6** 不做卖出导出功能（买入侧导出也尚未实现，标注"开发中"）。
- **NG-7** 不改动买入侧任何现有逻辑与数据。
- **NG-8** 不做卖出份额的前端硬校验拦截（前端可提示，最终以任务侧超卖校验为准）。

## 7. 数据需求（Data Requirements）

### 7.1 新建表：fund_seller（基金卖出流水表）

| 字段 | 类型 | 必填 | 默认 | 含义 |
|------|------|------|------|------|
| id | bigint PK auto_increment | 是 | - | 卖出流水号 |
| fund_code | varchar(10) | 是 | - | 基金代码 |
| fund_name | varchar(64) | 否 | '' | 基金名称（冗余） |
| time | date | 是 | curdate() | 卖出日期 |
| shares | decimal(15,4) | 是 | - | 卖出份额（手动录入） |

| realized_profit | decimal(15,2) | 否 | NULL | 已实现盈亏（任务计算：(nav−cost_price)×shares） |
| type | varchar(64) | 否 | '' | 卖出类型（'1'手动/'2'止盈/'3'止损） |
| policy | varchar(500) | 否 | '' | 适用策略脚本（预留） |
| sell_status | varchar(20) | 否 | 'PENDING' | 卖出状态（PENDING/SUCCESS/FAILED） |
| remark | varchar(500) | 否 | NULL | 备注 |
| del_flag | char(1) | 否 | '1' | 删除标志（1正常 0删除） |
| create_by / create_time / update_by / update_time | - | 否 | - | 通用审计字段 |

- 唯一键：`uk_fund_code_time(fund_code, time)`
- 查询索引：fund_code、del_flag、time、sell_status、(time,sell_status)、(fund_code,time,sell_status,del_flag)、(sell_status,shares)
- 注：卖出金额 `amt` 用 decimal(15,4)（买入金额是 decimal(7,4) 上限 9999，卖出可能整仓赎回金额较大，需更大精度）。

### 7.2 复用表（不修改结构）

- **position_daily_snapshot**：只读，累计收益图按 snapshot_date 聚合 SUM(profit_loss)。

### 7.3 任务配置

- `task_schedule` 表新增 `calculate_seller_amount_task`，cron `0 * * * *`（每小时），enabled=1。

## 9. 风险评估（Risk Assessment）

| 风险 | 类别 | 影响 | 缓解策略 |
|------|------|------|----------|
| 净值不可用导致卖出长期 PENDING | 技术 | 卖出金额/持仓扣减延迟 | 任务每次执行重试 PENDING 记录；净值匹配精确日期，基金净值更新任务先于本任务产出净值时自然消化 |
| 超卖导致持仓负份额 | 数据一致性 | 持仓数据错误 | 任务侧硬校验 `卖出份额≤持仓份额`，超卖标记 FAILED 不扣减 |
| 卖出与买入任务并发更新同一持仓 | 并发 | 持仓更新覆盖 | 与买入侧相同的单 session 顺序更新模式；两任务均每小时，实际并发概率低，且各自独立 session+commit |
| 删除卖出不回补，用户误删后持仓偏差 | 业务 | 持仓份额偏高 | 文档明确不回补规则；删除前二次确认；如需修正可手动编辑持仓 |
| position_daily_snapshot 仅 3 天数据，累计收益图趋势短 | UX | 图表点少 | 不回填历史（与持仓分析功能决策一致），随时间积累；图表对少数据点优雅降级 |
| 卖出金额精度（decimal(7,4) 不够） | 技术 | 大额赎回金额溢出 | 卖出 amt 用 decimal(15,4)，已规避 |
| 前端 dist 与源码不同步 | 部署 | 线上跑旧前端 | push 前必须 `npm run build` 并提交 dist/（项目构建门禁） |

## 10. 可访问性（Accessibility）

延续现有前端基线（Element Plus 组件），不设额外 WCAG 硬性指标，但遵循：

- 所有交互按钮有明确文字标签与 tooltip。
- 表格操作按钮使用 size="small" + 类型色区分（编辑默认、删除 danger）。

## 12. 技术考量（Technical Considerations）

- **架构对称性**：卖出 = 买入的反向。表结构、Storage 命名（FundSellerStorage）、Task 命名（calculate_seller_amount_task）、API 路径（/api/sellers）均与买入对称，便于维护。
- **加权平均成本法**：卖出时 cost_price 不变、cost_amount 按比例减少，符合通用基金核算惯例，且与买入侧加权逻辑自洽。
- **净值获取复用**：卖出侧的"按精确日期取净值"逻辑与买入侧 `_get_nav_value` 完全一致，可复用同一思路（独立实现于卖出 task 内，避免跨 task 耦合）。
- **持仓扣减时机**：在任务算出金额成功后才扣减，而非录入即扣减——与买入侧"算出份额后才更新持仓"对称，保证"无净值不扣减"的安全性。
- **双进程架构**：卖出金额任务注册在 scheduler 进程；卖出 CRUD 在 web 进程；手动刷新经 `/api/task/run/<func>` → scheduler_proxy → scheduler `/internal/task/run/<func>`（与买入刷新份额完全一致）。
- **累计收益图后端聚合**：新增按 snapshot_date 聚合全部持仓的查询（SUM(profit_loss) 等）；单持仓视角复用现有单持仓序列。计算逻辑放 `app/analytics/position_analysis.py` 纯函数层，便于 TDD。
- **TDD**：先在 `tests/test_position_analysis.py` 增加累计收益序列计算与已实现盈亏汇总的测试用例，再实现。
